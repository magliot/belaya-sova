# Тест Совы на коротком склоне

Отдельная рабочая сцена для сравнения с [браузерной версией](https://magliot.github.io/belaya-sova/review/). Основная игра и кнопка Telegram по-прежнему открывают браузерный спуск.

Открыть папку `unity/OwlSlope` в Unity Hub с редактором **6000.3.27f1** (6.3 LTS), дождаться установки зависимостей URP и открыть `Assets/Slope.unity` → Play. Для Windows: меню `Owl → Build Windows player`; запускать `Builds/Windows/OwlSlope.exe` вместе с соседними DLL и папкой данных. Бинарная сборка локальная, в Git хранится исходный проект. Проверка Windows-сборки: запустить `OwlSlope.exe --owl-smoke -batchmode -logFile player-check.log`. Проверка ждёт изменения костей, проверяет поворот, прыжок, посадку и сброс; результат этой сборки — `OWL PLAYER PASS`, код выхода 0. Для воспроизводимого сравнения выбрать Game View 375 × 667.

В локальной веб-сборке 2026-11-20e заезд начинается по кнопке «Поехали». Между 200 и 294 м стоят трое ворот. Касание задаёт начало жеста, перемещение пальца задаёт боковое смещение. Чувствительность берётся из настроек основной игры. При отпускании Сова продолжает движение по текущему курсу. На 255 м трамплин сам отправляет Сову в полёт, на 263 м можно поймать мандарин. Короткий тап в воздухе запускает грэб. На клавиатуре работают стрелки или A/D, пробел для грэба, P для паузы. «Ещё заезд» возвращает на старт, «В меню игры» — к выбору героя. Ранее собранный Windows-плеер демонстрирует исходный участок с автоматическим повтором.

## Запуск в Telegram

У тестового склона отдельный вход [Открыть Unity в Telegram](https://t.me/belaya_sovabot/play?startapp=unity). Ссылку можно открыть на Android или iPhone. Обычная кнопка бота ведёт в основную браузерную игру.

Для сборки установить Web Build Support для редактора 6000.3.27f1, выбрать веб-платформу и выполнить `Owl → Build Telegram Web pilot`. Команда для пакетного режима Unity: `-batchmode -quit -projectPath <проект> -buildTarget WebGL -executeMethod BakeSlope.BuildWeb`. В папку сайта `docs/unity-slope/` копируются `index.html` и папка `Build` из `Builds/Web/`, а также `StreamingAssets` при наличии. Шаблон использует мобильный размер окна, Telegram SDK и программную распаковку на статическом хостинге. Для проверки запустить `node tools/check-unity-web.cjs` при работающем сервере на порту 8766. Для проверки опубликованной версии передать адрес сайта сразу после имени скрипта.

## Что сравнивается

`Assets/Resources/Slope.json` — измеренная сетка поперечных сечений браузерного склона от 185 до 305 м, положение и направление камеры и координаты объектов. `tools/capture-slope-review.cjs` проекта снимает эталон на 200 м; `tools/unity-export.py` готовит FBX и текстуры из игровых моделей. В пилоте та же Сова с доской, ель, валун и снеговик. Свет, тени и материалы — Unity URP. `Owl → Build comparison scene` пересоздаёт сцену, записывает `docs/review/unity.png` и проверяет руление, прыжок, приземление и сброс. Для автоматизации редактора: `-batchmode -quit -projectPath <папка OwlSlope> -executeMethod BakeSlope.Run -logFile <файл>` (с доступным графическим устройством и лицензией).

Рисунок подготовленного снега и рыхлой обочины взят из двух Canvas-текстур основной игры. Горный фон использует выбранную иллюстрацию `docs/art/slope/ridge-52b.webp`. Лес за границами трассы собран из экземпляров той же модели ели. В мобильном профиле URP используются масштаб рендера 1 и MSAA 2×. Уклон задаёт скорость, а формулы бокового ускорения, чувствительности и ослабления управления в воздухе перенесены из основной игры. Пилот охватывает только фиксированный слалом Совы. Физический телефон для сопоставления FPS и задержки двух версий ещё предстоит проверить.

## Сколько займёт полноценный перенос

Предварительная оценка для одного разработчика при сохранении существующих моделей: 2–3 недели на физику, генерацию этапов и столкновения; 1–2 на персонажей, анимацию и интерфейс; 1–2 на сборку для Web, Telegram, сохранения и рейтинг; 1–2 на мобильную оптимизацию и регрессии. Всего **5–9 рабочих недель**, без создания новых моделей. До принятия решения: собрать Web-пилот для Telegram, на одном телефоне сравнить время до управляемого кадра, FPS и длинные кадры при одинаковом управлении и плотности объектов. По этому тесту оснований менять движок основной игры нет.
