# Unity Web · Telegram, профиль и рейтинг

Ветка `migration/unity-web`. Исходники оболочки находятся в `unity/OwlSlope/Assets/WebGLTemplates/MountainRace/`. Сцена передаёт состояние через `Assets/Plugins/WebGL/MountainUI.jslib`. Главное меню открывает сцену Unity. Осмотр доступен через «Ещё → Настройки → Осмотр трассы». Там можно сменить героя, выбрать основной склон, спринт или один из бонусов, перейти на точный метр, изменить полосу, скорость и эффект, сделать один шаг.

## Входы

| Адрес | Игра |
| --- | --- |
| Корень сайта, обычная кнопка бота | Действующая Three.js |
| `startapp=unity`, папка `unity-slope/` | Предыдущий Unity-пилот |
| `startapp=unitytest`, папка `unity-test/` | Новая Unity-сборка при размещении сайта с этой ветки |

Для локального запуска выполнить `node tools/serve.cjs docs 8784` и открыть [тестовый склон с seed 1911](http://127.0.0.1:8784/unity-test/?seed=1911). В опубликованном выпуске тестовая ссылка передаёт боту параметр `unitytest`. URL без параметра и режим `unity` обрабатываются отдельно. Состав архива и откат описаны в [АРХИВ_THREE.md](АРХИВ_THREE.md).

## Как переносится профиль

| Хранилище | Старая игра | Unity-тест |
| --- | --- | --- |
| Браузер, гость | `bsova_<поле>` | `bsova_unity_test_v1` |
| Браузер внутри Telegram | `bsova_tg<ID>_<поле>` | `bsova_tg<ID>_unity_test_v1` |
| Telegram CloudStorage того же бота и игрока, API от 6.9 | JSON в ключе `save`, поле `uid` обязательно совпадает | JSON в ключе `unity_test_v1` с `uid`, `schema`, `updated`, `data` и идентификатором последнего зачтённого заезда |

Импортируются `best`, `coins`, `hero`, `muted`, `mag`, `boost`, `helmets`, `sens`, `coll`, `fis`, `meet`, `mdone`, `missions`, `vol`. Для старого облачного профиля с равным или бо́льшим рекордом берутся его значения с локальным заполнением отсутствующих полей. Для меньшего рекорда сохраняется локальный профиль. В обоих случаях объединяются постоянные открытия `meet.goldenOwl` и `meet.prizeFeather`. Перо открывает обе бонусные трассы, золотая сова отдельно открывает снегоход. Новый профиль имеет приоритет по времени обновления, при следующем входе также подхватываются более высокий старый рекорд и новые открытия.

Гостевой прогресс доступен в границах прежнего origin браузера. При другом хосте данные Telegram переносит CloudStorage при входе через прежнего бота. При отказе облака через три секунды доступен локальный профиль. Опоздавший ответ учитывает выбор героя, изменения кошелька и постоянные награды текущего сеанса. При полном отказе чтения запись в неизвестный удалённый профиль откладывается до следующего входа. Если размер нового облачного профиля превышает 4096 байт, полная копия остаётся на устройстве и в настройках появляется сообщение.

## Рейтинг и приёмка

В тестовом `release.js` заданы `channel: 'test'` и пустой `leaderboardEndpoint`. Списки «Неделя» и «Всё время» собираются из личных заездов на этом устройстве. Осмотр исключён из наград и рейтинга. Кнопка «Поделиться» готовит PNG 1080×1350, за отправку в Telegram отвечает отдельная кнопка на карточке.

Для принятого выпуска собрать вариант с `channel: 'production'` и адресом `API_URL` из действующей версии `docs/index.html`. Продакшен использует собственный ключ `unity_release_v1` и повторно импортирует старый профиль. Тестовые очки и покупки остаются в тестовых ключах. Подписанные `initData` передаются прежнему Apps Script для операций `submit` и `leaderboard`. После 30 м при сворачивании используется `sendBeacon`. Интервал между промежуточными записями и перед итоговой отправкой — 5 секунд. Переключение основной кнопки выполняется отдельно после приёмки.

## Проверки

```powershell
node tools/check-unity-platform.cjs
node tools/check-unity-platform-catalog.cjs
$env:DANCE_BROWSER_MODULE=(Resolve-Path '../.browser-tools/playwright-local.cjs').Path
node tools/check-unity-platform-browser.cjs
node tools/check-unity-platform-browser.cjs http://127.0.0.1:8784/unity-test/
```

Модульный тест проверяет оба источника сохранений, чужой UID, пригодность старой коллекции без облачной копии, поздний ответ облака, оба бонуса, однократное начисление, форму боевых запросов и `sendBeacon` с паузой. Сетевые запросы перехватываются локально.

Браузерная проверка запускает архивную Three.js-игру, выбирает Сову, выполняет два трюка и забирает перо. Затем Unity-оболочка получает фактически заработанные профиль, рекорд и оба бонуса через настоящий SDK с тестовым транспортом Telegram. Без URL второй этап использует имитацию событий Unity. С URL он загружает собранный WebAssembly. В отдельном листе моделей 65 архивных карточек и 107 изображений Three.js, доступных по запросу из настроек.

Первый локальный WebAssembly прошёл испытание с контролируемым облаком. На экране 375×667 подтверждены герой, рекорд и доступность обоих бонусов после импорта, навигация «Назад», высота 565 пикселей, сворачивание, ручное продолжение, повтор и результат. Открыты магазин, задания, коллекция, FIS, танцы, замеры и карточки каталога. В осмотре проверены 2507 м, переход на 2607 м, смена героя и предельные 1161 м бонусной трассы. На финише сформирован PNG 1080×1350, исходное облако сохранилось, обращений к боевому рейтингу не было. Первый Web принимал точный метр при уходе фокуса. Проверка Enter обнаружила, что Unity захватывала клавиатуру HTML-полей.

В проверках на компьютере использован временный аккаунт тестового транспорта. Для проверки реального пользовательского облака нужен запуск из авторизованного аккаунта старого бота. Замер на Android и iPhone выполняется отдельно на физических устройствах. Вменять этим устройствам FPS браузерной эмуляции нельзя.
